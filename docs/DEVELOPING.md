# Developing Gantt-It

Notes for working on Gantt-It itself. For using it, see the [README](../README.md) and the
[User guide](USER-GUIDE.md).

Related documents:

- [RELEASING.md](RELEASING.md): cutting a release from a tag.
- [TRANSLATIONS.md](TRANSLATIONS.md): UI and chart languages, and how strings are translated.

## Layout

```text
src/
  GanttIt.Core/          net8.0;net10.0. No Revit, no WPF:
                         Model/ (charts, sections, links, palette, settings, units),
                         Scheduling/ (link propagation), Timeline/ (timescale rules, axis, labels),
                         Layout/ (layout engine, grid, geometry checks),
                         Dates/ (date formats, typed-date parsing), Editing/ (editor input,
                         recent colours, card summaries), Serialization/ (chart and settings JSON),
                         Localization/ (chart text per language, Resources/CoreStrings*.resx),
                         Theming/ (light and dark UI palettes), Picking/ (pick-from-screen
                         sampling and coordinate maths), Views/ (view fallback after Delete),
                         Validation/ (chart validation)
  GanttIt.Revit/         the add-in (net8.0-windows for 2025 and 2026, net10.0-windows for 2027)
    App.cs               "Gantt-It" panel on the Add-Ins tab
    Commands/            IExternalCommand entry points
    Resources/icons/     gantt_32.png, gantt_16.png, and gantt_32_dark.png, gantt_16_dark.png
                         for Revit's dark theme (all generated by tools/make_icons.py)
    Resources/Strings*.resx
                         UI strings in English, French, Spanish, German (docs/TRANSLATIONS.md)
    GanttIt.addin        manifest (VendorId DSOS)
tests/
  GanttIt.Core.Tests/    xUnit; runs on any OS
installer/               per-user MSI (WiX 6): Product.wxs, GanttIt.Installer.wixproj,
                         stage.sh, inspect-msi.ps1, branding/
tools/
  make_icons.py          regenerates the ribbon icons (Python + Pillow)
  gen_strings.py         regenerates the typed *.g.cs string accessors from the .resx files
  make_installer_branding.py
                         regenerates installer/branding/ from the same glyph
  vm/                    helpers for the W10C-Testing VM (pack, deploy, drive Revit,
                         compare Self-Test reports)
docs/                    user guide, this file, releasing, translations; images/
```

## Building

Configurations pick the Revit year, following rst-c's pattern:

| Configuration | Revit | Target framework |
|---|---|---|
| `Debug R25`, `Release R25` | 2025 | `net8.0-windows` |
| `Debug R26`, `Release R26` | 2026 | `net8.0-windows` |
| `Debug R27`, `Release R27` | 2027 | `net10.0-windows` |

```sh
dotnet test tests/GanttIt.Core.Tests -c "Release R26"
dotnet build GanttIt.sln -c "Debug R26"
```

Both .NET 8 and .NET 10 SDKs are needed (Core and its tests target both). The
Revit API comes from the reference-only `Nice3point.Revit.Api.*` packages, so
everything builds without Revit installed, including on Linux.

## CI and releases

`.github/workflows/build.yml` runs on every pull request and push to `main`,
through the reusable `_build.yml`: the Core tests on net8.0 and net10.0, a
build of all six configurations, and a Windows job that builds the MSI from
`Release R25`, `Release R26` and `Release R27` and uploads it as the
`GanttIt-msi` artifact (the manual-install zips as `GanttIt-zips`). Every job
is required. The `Debug R25`, `Debug R26` and `Debug R27` jobs upload the
add-in as the `GanttIt-Debug-R25` / `-R26` / `-R27` artifacts, laid out like an
`Addins\<year>\` folder:

```text
GanttIt.addin
GanttIt\GanttIt.Revit.dll, GanttIt.Core.dll, Resources\icons\…, fr\ es\ de\…
```

Releases are cut by pushing a `v*` tag: `.github/workflows/release.yml` builds
the tagged commit and publishes the GitHub Release with the MSI attached. The
version comes from the tag alone; see [RELEASING.md](RELEASING.md).

## Where the installer puts files

The MSI installs per user, in the add-ins folder of each supported Revit year
it finds (2025, 2026, 2027):

```text
%AppData%\Autodesk\Revit\Addins\<year>\GanttIt.addin
%AppData%\Autodesk\Revit\Addins\<year>\GanttIt\         add-in DLLs, PDBs, icons, fr\ es\ de\ UI resources
```

A year counts as installed when `Revit.exe` is found, by standard Windows
Installer searches (`installer/Product.wxs`, no custom actions): first in the
`InstallLocation` of the Revit uninstall entry
`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\{7346B4A0-<yy>00-0510-0000-705C0D862004}`
(64-bit registry), then in `C:\Program Files\Autodesk\Revit <year>\`. Each
year's components carry the condition `REVIT<year>FOUND OR REMOVE~="ALL"` and
are transitive:

- **First install:** only the found years are installed. With none found, a
  launch condition stops the install ("Gantt-It needs Revit 2025, 2026 or
  2027, and none was found on this computer."). It never blocks a repair or
  an uninstall, and an uninstall removes every year Gantt-It installed, even
  one whose Revit was uninstalled first (the `REMOVE~="ALL"` half).
- **Revit installed later:** run the same MSI again and choose **Repair**
  (or `msiexec /fecmus GanttIt-<version>.msi`, the same mode as the UI's Repair;
  `/fa` alone does not rewrite per-user registry values, so a dropped year's
  `HKCU\Software\Designs/OS\Gantt-It\<year>` marker stays behind). A repair re-evaluates the
  transitive conditions, so it adds the new year, and removes a year whose
  Revit is gone.
- **Upgrade:** a newer MSI removes the old version completely (before it
  installs anything), then installs for the years it finds now. With no
  supported Revit left, the launch condition blocks the upgrade too, and the
  installed version stays. This also cleans up v1.0.0, which installed
  2026 and 2027 unconditionally.

`installer/inspect-msi.ps1` checks this wiring in CI (component conditions and
the transitive bit, the AppSearch tables, the launch condition, the Upgrade
table and where RemoveExistingProducts runs); the
installs themselves are tested on a Windows machine with Revit.

Each release also carries `GanttIt-<version>-Revit2025.zip`,
`GanttIt-<version>-Revit2026.zip` and `GanttIt-<version>-Revit2027.zip` for a
manual install: unzip into `%AppData%\Autodesk\Revit\Addins\<year>\`.

## Dev deployment

Copy a `GanttIt-Debug-R25` / `-R26` / `-R27` artifact's contents into
`%AppData%\Autodesk\Revit\Addins\<year>\`. Revit locks loaded DLLs, so close
Revit before redeploying. The add-in is unsigned for now, so Revit asks whether
to load it on first launch. Debug builds add a **Gantt-It Self-Test** button to
the panel.

The scripts in `tools/vm/` stage, deploy and drive these builds on the
W10C-Testing VM; each script's header explains its use.
